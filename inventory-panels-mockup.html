Mockup — inventory side-panel toggles · 4 patterns · click the buttons in each frame

Current state: vertical-text tabs in a reserved right gutter. Two UX problems remain: rotated labels are slow to read, and the toggles sit far from the toolbar where every other action lives. Below are four conventional patterns, each as a working miniature. All keep the ready-count badge, Esc-to-close and one-panel-at-a-time behaviour.

A

Toolbar toggles · overlay drawer

Workbench / Stats become ordinary buttons in the manifest toolbar — horizontal labels, grouped with the other actions. The drawer still slides over the grid (closest to today's behaviour).

C

Icon activity bar · docked panel

The IDE pattern (VS Code): a slim icon-only rail, always visible, with count badges and tooltips. The panel docks between the grid and the rail. Scales well if more panels arrive later (loadout, map, notes…).

D

Single tabbed inspector

Since only one panel can be open at a time anyway, merge them: one docked inspector with tabs inside. Toolbar buttons deep-link to a tab; switching tabs never moves the panel. Cleanest mental model, one close button, one width.

Recommendation

Option D is the strongest fit: the two drawers are already mutually exclusive in the code (activeDrawer), so one tabbed inspector matches the real model. It fixes both original issues — vertical text and orphaned controls — and the docked layout means the workbench can be read against a fully visible grid.

Option B is the runner-up if you prefer keeping two separate drawers. C only earns its permanent gutter if more panels are coming.

All docked variants fall back to overlay below ~900px viewport width, where there isn't room to split.
